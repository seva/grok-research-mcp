# WaLRuS-DATA — 2026-04-25

## Wins
- `auth/store.py` is now platform-aware: macOS uses `keyring` (Keychain), Windows retains DPAPI verbatim
- `store_win32.py` is the original `store.py` with only the `is_expired`/`AuthRequired` definitions extracted — zero functional change
- `store_base.py` holds `AuthRequired` and `is_expired` — shared, platform-agnostic
- `store_darwin.py` is a clean new file; no Windows code was modified
- Full suite: 60 passed, 4 skipped (Windows tests correctly skipped on macOS)
- `pywin32` moved to `[project.optional-dependencies.windows]`; `keyring>=24.0` added to core deps

## Learnings
- `store_darwin.py` initially imported `is_expired`/`AuthRequired` from `store_win32`, pulling in `win32crypt` at import time on macOS — caught immediately by test collection failure
- Fix: extract shared symbols into `store_base.py`; both platform modules import from there
- `keyring` mocking target must be the module-level name in `store_darwin` (`grok_research_mcp.auth.store_darwin.keyring`), not the top-level `keyring` package

## Risks
- Windows DPAPI branch is untested in this session — no Windows machine, no CI
- `keyring` on macOS will prompt the user for Keychain access on first `save()`/`load()` if the app isn't yet trusted — expected behavior, not a bug, but worth documenting for users

## Strategy
- Add GitHub Actions Windows CI job (`pytest tests/auth/`) before next Windows-touching change
- Linux support would add `store_linux.py` with `keyring` (same interface as `store_darwin.py`) — likely a one-liner dispatcher change

## Decisions
- Split into `store_win32.py` / `store_darwin.py` / `store_base.py` rather than a single file with `if sys.platform` branches — eliminates Windows regression risk, maximizes readability
- macOS scope only for this session; Linux deferred

## Alignment
- No Windows behavior was changed — only code structure changed to isolate the import
- `store_win32.py` is the original `store.py` verbatim except `is_expired`/`AuthRequired` now imported from `store_base`

## Tradeoffs
- One extra file (`store_base.py`) for zero Windows risk — accepted
- `keyring` added as a core dep (not optional) — justified because it's the only non-Windows path and is lightweight

## Alternatives
- Single `store.py` with `if sys.platform == "win32": import win32crypt` guard — rejected due to unverifiable Windows regression risk
- `keyring` as optional dep with a fallback — rejected, unnecessary complexity
